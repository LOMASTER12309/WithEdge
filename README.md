# WithEdge

Реализация операции **WITH EDGE** на C++11 для проверки топологии интегральных схем. Операция выбирает из первого слоя полигоны, у которых есть общие рёбра или участки рёбер с полигонами второго слоя.

Проект выполнен в рамках работы «Верификация топологии интегральной схемы» в ННГУ им. Н. И. Лобачевского. Функция предназначена для модуля `drc_solver` системы Synthesis и использует структуры геометрического ядра `gkernel`.

## Операция WITH EDGE

```cpp
gkernel::ContourLayer withEdge(
    const gkernel::ContourLayer& layer1,
    const gkernel::ContourLayer& layer2,
    const drc_solver::ConstrParams* params = nullptr);
```

| Параметр | Назначение |
| --- | --- |
| `layer1` | Слой контуров, из которого выбираются объекты результата. |
| `layer2` | Слой, с рёбрами которого сравниваются рёбра первого слоя. |
| `params` | Необязательное ограничение на число рёбер контура, имеющих общий участок со вторым слоем. |

Без `params` достаточно одного общего участка. При передаче ограничения функция считает подходящие рёбра каждого контура и проверяет полученное число через `satisfy()` из `include/params.hpp`.

Особенности отбора:

- Учитываются как полностью совпадающие рёбра, так и частичные перекрытия на одной прямой.
- Касание в одной точке не считается общим участком.
- Поддерживаются горизонтальные, вертикальные и наклонные рёбра; направление обхода не влияет на совпадение.
- Каждое ребро `layer1` учитывается не более одного раза, даже если оно перекрывается с несколькими рёбрами `layer2`.
- Результат содержит целые исходные контуры в порядке их следования в `layer1`. Их геометрия не меняется.

Ограничение `[0, 0]` позволяет выбрать контуры без общих рёбер. Если второй слой пуст, без параметров результат будет пустым, а с ограничением, допускающим ноль, вернётся весь первый слой.

### Пример

Два квадрата имеют общую вертикальную сторону при `x = 2`. В результат попадает квадрат из первого слоя:

```cpp
#include <iostream>
#include <vector>

#include "base.hpp"
#include "params.hpp"
#include "with_edge.cpp"

int main() {
    using namespace gkernel;
    using namespace drc_solver;

    Contour left(std::vector<Point>{{0, 0}, {2, 0}, {2, 2}, {0, 2}});
    Contour right(std::vector<Point>{{2, 0}, {4, 0}, {4, 2}, {2, 2}});

    ContourLayer layer1({left});
    ContourLayer layer2({right});

    auto result = withEdge(layer1, layer2);
    std::cout << result.size() << '\n';  // 1 контур

    ConstrParams exactlyOne(1, 1, true, true);
    auto filtered = withEdge(layer1, layer2, &exactlyOne);
    std::cout << filtered.size() << '\n';  // 1 контур
}
```

В текущей сборке `with_edge.cpp` подключается непосредственно в файл приложения, как в `src/main.cpp` и тестах. При таком подключении отдельно компилировать его не нужно. Для примера выше добавьте `include/` и `src/` в пути поиска заголовков.

Конструктор `ConstrParams(v1, v2, inV1, inV2)` задаёт границы и их включение в интервал:

| Ограничение | Конструктор |
| --- | --- |
| Ровно одно ребро | `ConstrParams(1, 1, true, true)` |
| От одного до трёх включительно | `ConstrParams(1, 3, true, true)` |
| От одного включительно до трёх не включительно | `ConstrParams(1, 3, true, false)` |
| Ни одного ребра | `ConstrParams(0, 0, true, true)` |

Параметры задаются числовым конструктором: метод `ConstrParams::init(std::string)` в этой реализации оставлен заглушкой.

## Как устроен алгоритм

Поиск сводится к сравнению одномерных интервалов на общих опорных прямых:

1. Для каждого невырожденного ребра строится `LineId`: нормаль к прямой, знаковое расстояние до неё и интервал проекции на одну из координатных осей. Направление приводится к единому виду, компоненты нормали квантуются с масштабом `10^12`.
2. Для обоих слоёв формируются массивы записей. В первом сохраняется также индекс исходного контура, чтобы затем собрать результат.
3. Записи сортируются по опорной прямой и началу интервала.
4. Алгоритм проходит по двум массивам, сопоставляя группы рёбер на одинаковых прямых. Внутри совпавших групп общий участок ищется проходом с двумя указателями.

Сложность по времени — `O(E log E)`, где `E` — суммарное число рёбер двух слоёв. После сортировки поиск занимает линейное время. Дополнительная память — `O(E + C)`, где `C` — число контуров первого слоя.

На больших слоях подготовка записей распределяется между задачами `std::async`: каждая пишет в свой диапазон заранее выделенного массива. Сортировки двух слоёв запускаются одновременно и используют `__gnu_parallel::sort` с OpenMP. Для горизонтальных и вертикальных рёбер предусмотрен отдельный путь без нормирования вектора, а без `params` повторные проверки уже найденного контура пропускаются.

Координаты хранятся в `double`. Для геометрических сравнений используется допуск `eps = 1e-5` из `include/base.hpp`; вычисления опорной прямой и проверки перекрытия находятся в `src/line_helper.cpp` и `src/with_edge.cpp`.

## Сборка и запуск

Для сборки нужны:

- Linux x86-64: библиотеки Synthesis в репозитории поставляются в виде готовых `.so` для этой платформы.
- GCC с поддержкой C++11, GNU parallel algorithms (`<parallel/algorithm>`) и OpenMP.
- CMake 3.16 или новее.
- Заголовки и библиотека Google glog. Если пакет не предоставляет CMake-цель `glog::glog`, используется поиск через `pkg-config` (`libglog`).
- Для автоматических тестов — Catch2 **v2**, файл `catch2/catch.hpp`.

Заголовки Synthesis находятся в `include/`, библиотеки — в `lib/`. CMake использует пакет из `lib/Release/cmake/synthesis` и добавляет `lib/Release` в RPATH исполняемых файлов. Готовые библиотеки должны быть совместимы с системными `glibc` и `libstdc++`.

Из корня проекта:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build --parallel
./build/with_edge_demo
```

В текущем примере из `src/main.cpp` квадраты касаются только углом, поэтому результат пустой.

Путь к Catch2 в `CMakeLists.txt` задан как `/usr/local/include`: для сборки цели `tests` заголовок должен находиться в `/usr/local/include/catch2/catch.hpp`. В исходном файле тестов приведена установка версии 2.13.10. Если заголовка нет, CMake выдаёт предупреждение и собирает остальные программы без цели `tests`. После установки заголовка нужно повторить конфигурацию и сборку.

## Тестирование

В `tests/tests.cpp` находятся 22 функциональных теста Catch2. Они проверяют полное и частичное совпадение рёбер, отбор нескольких контуров, пустые слои, касание углом, наклонные рёбра, дубликаты во втором слое, малый общий участок и интервальные ограничения. В этих тестах проверяется количество контуров в результате.

Запуск функциональных тестов без случаев со случайной генерацией:

```bash
./build/tests '~[random]~[random_grid]'
```

Ручная проверка построения `LineId` для разных направлений рёбер:

```bash
./build/tests_main
```

### Замеры времени и памяти

Для замеров на случайных данных используются два тега Catch2:

```bash
./build/tests '[random_grid]'
./build/tests '[random]'
```

`[random_grid]` создаёт небольшие слои с разными сетками. `[random]` — нагрузочный случай: по 3 млн прямоугольных контуров в каждом слое, всего 24 млн рёбер. Оба запуска выводят время вызова `withEdge` в микросекундах, без генерации входных данных; проверок ожидаемого результата в них нет. Запуск `./build/tests` без фильтра включает и нагрузочный случай.

Отдельная программа `test_memory` измеряет время генерации, время работы функции и память процесса по `/proc/self/status` (`VmRSS`, `VmHWM`). Каждый замер выполняется в дочернем процессе. Например, для сетки 100 × 100 в каждом слое:

```bash
./build/test_memory 100 100 10 10 0.2 0.8 42 43
```

Аргументы по порядку: число строк и столбцов сетки, ширина и высота ячейки, минимальный и максимальный относительный размер прямоугольника в ячейке, два зерна генератора. Без аргументов используется сетка 2000 × 1500 в каждом слое — также 24 млн рёбер суммарно. Для таких запусков нужна память под миллионы контуров и массивы записей рёбер.
